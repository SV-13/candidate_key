# REVIEW.md

## Scope and status

This review tracks defects found in the original starter and the current implementation status after the fixes completed so far. “Implemented” means the code change is present and the listed evidence has been checked; where evidence is a manual check rather than a dedicated automated regression test, that distinction is called out. The attendance-list items and remaining API endpoints are not complete yet.

## Behaviours checked but not classified as defects

- `GET /` and `GET /favicon.ico` return `404`. These are not defects because the API contract does not require a root page or favicon; `/health` is the specified readiness endpoint.
- An early punch-in produces `late_minutes: 0`. That is expected: an employee who punches in before shift start is not late.
- `doc.pop("_id", None)` in `create_employee` is not a defect. Removing MongoDB's internal identifier from the public response is appropriate; the endpoint's public response should not expose `_id`.
- `load_dotenv()` not overriding existing environment variables is expected default behavior. Explicit environment values should continue to take precedence over `.env` values unless `override=True` is deliberately requested.

## Remaining work before punch-out

1. Complete and test `GET /attendance`: database-side pagination/sorting, filtered totals, query validation, public timestamp serialization, and defaults for legacy fields.
2. Add endpoint-level automated tests for employee creation, punch-in missing-employee behavior, response schemas, and concurrent duplicate handling where practical. `race_test.py` currently verifies concurrency manually against the running API and real MongoDB.
3. Decide and document startup behavior when MongoDB is unavailable.
4. Before coding `POST /attendance/punch-out`, write its operation order in plain English. It must explain how to query for the most recent record whose `punch_in` is at or before the supplied timestamp, which index supports that query, and which single MongoDB operation performs the conditional close atomically.
